## 3. 已确认问题

### T-01 · 高 · 悬赏发布重试重复冻结

同一学生提交赏金 14.00 元、内容完全相同的一次发布操作及其传输重试，两次均返回 HTTP 200 / 业务码 0，得到不同的帖子和订单 ID。可用余额从 **149.85 降至 121.85 元**，冻结从 **0.00 增至 28.00 元**，而一次操作应只冻结 14.00 元。两笔订单均可取消并分别原额退款。影响范围是发布请求结果不确定后再次提交。服务下单的 `Idempotency-Key` 并发与响应丢失重试已单独验证通过。[PRD §2.2](./校园悬赏平台-产品需求文档-PRD.md#22-订单状态与操作规则) · [TradePostService.java](../campus-bounty-user-backend/src/main/java/com/campus/bounty/trade/TradePostService.java#L22)

### T-02 · 中 · 图片上传实际单文件上限为 1 MiB

12 KB 左右的 PNG 上传后可公开读取，返回字节与原图一致。上传 **2,118,353 字节**的正常 PNG 时返回 HTTP **500** / `50000`。日志显示 Tomcat 单文件限制 **1,048,576 字节**，在业务存储层的 5 MiB 校验前拒绝请求。接口和页面允许 5 MB，因此头像、社区帖与交易帖都可能遇到这一错误。Nginx 配置的请求体上限为 6 MiB，失败已在直接连接后端时复现。[接口文档 §6.9](./用户端后端接口文档.md#69-上传图片) · [application.yml](../campus-bounty-user-backend/src/main/resources/application.yml) · [FileStorageService.java](../campus-bounty-user-backend/src/main/java/com/campus/bounty/common/FileStorageService.java#L30)

### T-03 · 中 · 合规字符数的多字节密码导致注册 500

学生注册使用 24 个汉字的密码时返回成功，使用 25 个汉字时返回 HTTP **500** / `50000`。25 个汉字仍在文档规定的 6–32 字符内，但 UTF-8 长度为 75 字节，超过 BCrypt 的 72 字节限制。接口 DTO 和注册页面只限制字符数。[用户端接口文档](./用户端后端接口文档.md#L123) · [RegisterReq.java](../campus-bounty-user-backend/src/main/java/com/campus/bounty/user/dto/RegisterReq.java#L14) · [UserService.java](../campus-bounty-user-backend/src/main/java/com/campus/bounty/user/UserService.java#L32)

### T-04 · 中 · 通知列表已更新，顶部红点仍可隐藏

另一学生接单后，发布者进入通知页，看到新消息且标为未读，顶部按钮仍无红点。Edge 重复确认该现象，完整刷新后立即显示红点，点击仍能标为已读并打开准确的订单。通知列表独立获取数据，顶部刷新有 30 秒冷却并按 45 秒间隔轮询，两个区域在此期间可能显示不同状态。[PRD §3.10](./校园悬赏平台-产品需求文档-PRD.md#310-站内通知pb-23) · [App.vue](../frontend/App.vue#L58) · [communication.js](../frontend/communication.js#L382)

### T-05 · 中 · 旧举报历史详情遗漏联动动作

从旧管理分支 `fe42bf0` 的审计格式构造一条历史举报并升级。升级后审批结论 `VALID` 和原始审计记录仍在，管理详情返回 `moderationAction: null`。同一动作换成现行审计格式后，详情正确返回 `CLOSE_TRADE_POST`。影响使用过该旧格式的环境，现行治理行为和新记录已实测通过。[AdminQueries.java](../campus-bounty-user-backend/src/main/java/com/campus/bounty/admin/AdminQueries.java#L153) · [admin.js](../frontend/admin.js#L248)

### T-06 · 中 · 超出 JavaScript 安全精度时，显示金额可能差一分

在 Node 中用与前端一致的 JSON 解析和金额格式化路径验证，数据库允许的 `100000000000000.01` 显示为 `¥100,000,000,000,000.02`。场景涉及扩容后的大额余额及使用相同转换路径的汇总金额。本项为前端数值路径验证，未构造长期形成的大额余额。常规金额和本次 MySQL 账务核对均准确。[PRD §2.3](./校园悬赏平台-产品需求文档-PRD.md#23-资金与流水规则) · [core.js](../frontend/core.js#L52)
