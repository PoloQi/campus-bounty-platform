# 校园悬赏平台用户端后端接口文档

> 更新日期：2026-11-14  
> 适用对象：用户端前端、管理员端前端及后端开发人员  
> 文档依据：`campus-bounty-user-backend` 当前源码  
> 默认服务地址：`http://localhost:8080`

## 1. 通用约定

### 1.1 请求与鉴权

- 业务接口统一以 `/api` 开头。
- 除 `POST /api/auth/register`、`POST /api/auth/login` 外，本文 REST 接口均需在请求头携带 JWT：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

- 管理接口还要求登录用户的 `role=ADMIN`，不能仅由前端根据 `role` 放行。
- 图片访问路径 `/uploads/**` 无需鉴权；WebSocket 使用查询参数鉴权，见第 11 节。
- 后端未单独配置 CORS。浏览器跨域直连失败时，推荐由前端开发服务器将 `/api`、`/uploads` 和 `/ws` 代理到后端。

### 1.2 统一响应

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

失败响应：

```json
{
  "code": 40000,
  "message": "具体错误信息",
  "data": null
}
```

| 情况 | HTTP 状态 | 业务 `code` | 前端处理建议 |
|---|---:|---:|---|
| 成功 | 200 | 0 | 读取 `data` |
| 业务规则不满足 | 200 | 40000 | 展示 `message`，必要时刷新详情 |
| 请求体参数校验失败 | 200 | 40000 | 展示 `message` 并修正输入 |
| 未登录、token 无效/过期、账号已封禁 | 401 | 40100 | 清理登录态并重新登录 |
| 非管理员访问 `/api/admin/**` | 403 | 40300 | 提示无管理员权限 |
| 其他服务端异常 | 200 | 50000 | 提示服务器错误并记录联调信息 |

**axios 等客户端必须同时判断 HTTP 状态和业务 `code`，不能只判断 HTTP 200。**

无返回数据的写操作成功时为：

```json
{"code": 0, "message": "ok", "data": null}
```

### 1.3 数据格式

- 路径中的 `{id}`、`{postId}`、`{orderId}` 等均替换为数值 ID。
- 金额使用 JSON 数值，最多两位小数；不要用浮点数自行做资金计算。
- 时间为不带时区后缀的 ISO 本地日期时间，例如 `2026-12-31T18:00:00`。
- 当前所有列表接口直接返回数组，**没有分页参数**。
- 交易帖 `images`、社区帖 `images` 和 `tags` 均为字符串。多个值可按团队约定用英文逗号拼接，后端不拆分数组。
- 可空字段可能返回 `null`，前端需做空值处理。

## 2. 账户与个人资料

### 2.1 注册

```http
POST /api/auth/register
```

无需 token。请求体：

```json
{
  "username": "student01",
  "password": "123456",
  "confirmPassword": "123456",
  "nickname": "同学甲"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `username` | 是 | 4–20 位，唯一 |
| `password` | 是 | 6–32 位 |
| `confirmPassword` | 是 | 必须与 `password` 一致 |
| `nickname` | 否 | 最多 20 字；为空时使用用户名 |

成功：`data` 为新用户 ID（`number`）。注册角色固定为 `STUDENT`，状态为 `ACTIVE`，同时创建零余额钱包。没有管理员注册接口。

### 2.2 登录

```http
POST /api/auth/login
```

无需 token，用户端和管理端共用。

```json
{
  "username": "student01",
  "password": "123456"
}
```

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "token": "<JWT>",
    "userId": 1,
    "nickname": "同学甲",
    "role": "STUDENT"
  }
}
```

`role` 为 `STUDENT` 或 `ADMIN`。默认 JWT 有效期为 1440 分钟，以实际部署配置为准。封禁账号不能登录；账号被封禁后，其已签发 token 也会立即失效。

### 2.3 查询本人资料

```http
GET /api/users/me
```

成功：`data` 为 `UserProfile`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 用户 ID |
| `username` | string | 用户名 |
| `nickname` | string/null | 昵称 |
| `avatar` | string/null | 头像地址 |
| `bio` | string/null | 个人简介 |
| `contact` | string/null | 联系方式 |
| `role` | string | `STUDENT` / `ADMIN` |
| `createdAt` | string | 注册时间 |

该响应不包含用户状态和钱包信息。

### 2.4 修改本人资料

```http
PUT /api/users/me
```

四个字段均可选，只更新请求中出现的字段：

```json
{
  "nickname": "新昵称",
  "avatar": "/uploads/example.png",
  "bio": "个人简介",
  "contact": "联系方式"
}
```

| 字段 | 最大长度 |
|---|---:|
| `nickname` | 30 |
| `avatar` | 200 |
| `bio` | 200 |
| `contact` | 60 |

传入空白字符串会清空对应字段；省略字段表示不修改。成功返回更新后的完整 `UserProfile`。

## 3. 钱包

### 3.1 查询本人钱包

```http
GET /api/wallet
```

成功：`data` 为：

```json
{
  "id": 1,
  "userId": 1,
  "balance": 100.00,
  "frozen": 5.00
}
```

`balance` 为可用余额，`frozen` 为交易中冻结金额。

### 3.2 模拟充值

```http
POST /api/wallet/recharge
```

```json
{"amount": 100.00}
```

`amount` 必填、大于 0、最多两位小数。成功返回最新钱包，并新增 `RECHARGE` 流水。该接口不涉及真实支付。

### 3.3 查询本人流水

```http
GET /api/wallet/logs
```

成功：`data` 为按 ID 倒序排列的 `WalletLog[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 流水 ID |
| `userId` | number | 钱包所属用户 ID |
| `type` | string | `RECHARGE` / `FREEZE` / `UNFREEZE` / `PAY` / `INCOME` |
| `amount` | number | 带符号金额，正数表示入账语义，负数表示出账语义 |
| `balanceAfter` | number | 变动后的**可用余额** |
| `orderId` | number/null | 关联订单；充值时为空 |
| `remark` | string/null | 备注 |
| `createdAt` | string | 创建时间 |

## 4. 悬赏、服务与订单

### 4.1 发布悬赏

```http
POST /api/trade/posts
```

```json
{
  "title": "帮取快递",
  "description": "取件后送到宿舍",
  "images": "/uploads/a.png,/uploads/b.png",
  "price": 5.00,
  "category": "跑腿",
  "deadline": "2026-12-31T18:00:00"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `title` | 是 | 最多 80 字 |
| `description` | 是 | 最多 1000 字 |
| `images` | 否 | 最多 500 字，图片地址字符串 |
| `price` | 是 | 大于 0，最多两位小数 |
| `category` | 是 | 最多 30 字 |
| `deadline` | 是 | 本地日期时间；当前不会自动结束订单 |

成功：`data` 为交易帖 ID。后端同时创建 `PENDING` 订单并冻结发布者赏金；发布者即订单 `buyerId`，`sellerId` 初始为 `null`。

### 4.2 发布服务

```http
POST /api/trade/services
```

```json
{
  "title": "高等数学答疑",
  "description": "线上一对一答疑一小时",
  "images": "",
  "price": 20.00,
  "category": "学习辅导"
}
```

字段规则与发布悬赏相同，但没有 `deadline`。成功：`data` 为服务帖 ID。发布服务不会立即创建订单，也不会冻结发布者资金。

### 4.3 交易大厅

```http
GET /api/trade/posts?type=BOUNTY&category=跑腿&keyword=快递
```

查询参数均可选：

| 参数 | 说明 |
|---|---|
| `type` | `BOUNTY`（悬赏）或 `SERVICE`（服务）；省略表示两类 |
| `category` | 分类精确匹配 |
| `keyword` | 标题模糊匹配，不搜索描述 |

成功：`data` 为按 ID 倒序排列的 `TradePost[]`，只包含 `OPEN` 帖子。

### 4.4 交易帖详情

```http
GET /api/trade/posts/{id}
```

所有已登录用户均可查询。成功：`data` 为：

```json
{
  "post": {"id": 1, "type": "BOUNTY"},
  "order": {"id": 2, "postId": 1, "status": "PENDING"}
}
```

悬赏返回关联订单；服务的 `order` 固定为 `null`，因为同一服务可以产生多笔订单，服务购买者应从“我的订单”进入订单详情。

### 4.5 购买服务

```http
POST /api/trade/posts/{postId}/buy
```

无请求体。仅适用于 `OPEN` 状态的 `SERVICE` 帖，且不能购买自己发布的服务。

成功：创建并返回 `IN_PROGRESS` 订单，`buyerId` 为当前用户，`sellerId` 为服务发布者，同时冻结买家资金并通知卖家。购买后服务仍保持 `OPEN`，可继续被其他用户购买。

### 4.6 查询订单详情

```http
GET /api/trade/orders/{id}
```

仅订单买卖双方可查。成功：`data` 为 `{ "order": TradeOrder, "post": TradePost }`。

### 4.7 订单操作

以下接口均无请求体，成功时 `data` 为最新 `TradeOrder`：

| 方法与路径 | 操作者与前置状态 | 结果 |
|---|---|---|
| `POST /api/trade/orders/{id}/accept` | 非 buyer；`PENDING` 悬赏 | seller 设为当前用户；订单转 `IN_PROGRESS`；帖子转 `LOCKED` |
| `POST /api/trade/orders/{id}/deliver` | 仅 seller；`IN_PROGRESS` | 订单转 `CONFIRMING`，资金保持冻结 |
| `POST /api/trade/orders/{id}/confirm` | 仅 buyer；`CONFIRMING` | 资金结算给 seller；订单转 `COMPLETED`；悬赏帖关闭 |
| `POST /api/trade/orders/{id}/cancel` | 仅 buyer；`PENDING` / `IN_PROGRESS` | 解冻退款；订单转 `CANCELLED`；悬赏帖关闭 |

前端按钮显示规则：

| 当前用户与订单状态 | 可显示操作 |
|---|---|
| 非 buyer，悬赏 `PENDING` | 接单 |
| seller，`IN_PROGRESS` | 标记交付、发起申诉 |
| buyer，`CONFIRMING` | 确认完成、发起申诉 |
| buyer，`PENDING` / `IN_PROGRESS` | 取消；`IN_PROGRESS` 时还可申诉 |

操作成功后建议刷新订单、个人中心、钱包及相关列表。按钮隐藏不能代替后端校验；重复请求或状态已变化时应展示错误并刷新。

### 4.8 我的订单与发布

```http
GET /api/trade/orders/mine
```

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "asBuyer": [],
    "asSeller": [],
    "published": []
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `asBuyer` | `TradeOrder[]` | 当前用户作为买家的订单，包括发布的悬赏和购买的服务 |
| `asSeller` | `TradeOrder[]` | 当前用户作为卖家的订单，包括接取的悬赏和售出的服务 |
| `published` | `TradePost[]` | 当前用户发布的全部悬赏与服务帖，含非 `OPEN` 状态 |

各数组按 ID 倒序返回。

### 4.9 交易对象模型

`TradePost`：

| 字段 | 类型/取值 |
|---|---|
| `id`, `publisherId` | number |
| `type` | `BOUNTY` / `SERVICE` |
| `title`, `description`, `images`, `category` | string；`images` 可空 |
| `price` | number |
| `deadline` | string/null；服务帖为空 |
| `status` | `OPEN` / `LOCKED` / `CLOSED` |
| `createdAt` | string |

`TradeOrder`：

| 字段 | 类型/取值 |
|---|---|
| `id`, `postId`, `buyerId` | number |
| `sellerId` | number/null；待接悬赏为空 |
| `amount` | number |
| `status` | `PENDING` / `IN_PROGRESS` / `CONFIRMING` / `DISPUTED` / `COMPLETED` / `CANCELLED` |
| `createdAt`, `updatedAt` | string |

## 5. 订单申诉

### 5.1 发起申诉

```http
POST /api/trade/orders/{id}/appeal
```

```json
{"reason": "对方未按约定完成服务"}
```

`reason` 必填，非空白，最多 500 字。仅订单买卖双方可对 `IN_PROGRESS` 或 `CONFIRMING` 订单发起申诉，同一订单不能同时存在多条 `OPEN` 申诉。

成功：返回 `Appeal`，订单转为 `DISPUTED`，资金保持冻结，并通知另一方。纠纷期间接单、交付、确认和取消均不可执行。

### 5.2 查询订单当前申诉

```http
GET /api/trade/orders/{id}/appeal
```

仅订单买卖双方可查。成功时有进行中的申诉则返回 `Appeal`，否则 `data=null`。该接口只查询 `OPEN` 申诉，不是申诉历史列表。

### 5.3 撤回申诉

```http
POST /api/trade/appeals/{id}/withdraw
```

无请求体。仅申诉人可撤回自己的 `OPEN` 申诉。成功后申诉转为 `WITHDRAWN`，订单恢复申诉前的 `IN_PROGRESS` 或 `CONFIRMING`，并通知另一方。

`Appeal` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id`, `orderId`, `appellantId` | number | 申诉、订单、申诉人 ID |
| `reason` | string | 申诉理由 |
| `fromStatus` | string | 申诉前订单状态 |
| `status` | string | 当前学生侧产生 `OPEN` / `WITHDRAWN` |
| `outcome` | string/null | 仲裁结果，管理端仲裁功能预留 |
| `adminId` | number/null | 处理管理员 ID |
| `adminComment` | string/null | 管理员处理意见 |
| `createdAt` | string | 发起时间 |
| `handledAt` | string/null | 撤回或处理时间 |

## 6. 社区与图片上传

### 6.1 发布社区帖

```http
POST /api/community/posts
```

```json
{
  "content": "今晚操场有一起跑步的吗？",
  "images": "/uploads/example.png",
  "tags": "运动,组队"
}
```

`content` 必填、最多 2000 字；`images` 可选、最多 1000 字；`tags` 可选、最多 200 字。成功返回原始 `Post` 对象，不含作者昵称和评论数。

### 6.2 社区动态列表

```http
GET /api/community/posts?tag=运动
```

`tag` 可选；传入时对 `tags` 字符串做包含匹配。成功返回按 ID 倒序排列的 `PostResp[]`，只包含 `VISIBLE` 帖子。

### 6.3 我的社区帖

```http
GET /api/community/posts/mine
```

成功返回当前用户发布的 `PostResp[]`，按 ID 倒序，包含已逻辑删除的帖子；前端可根据 `status` 区分展示。

`PostResp` 字段：`id`、`authorId`、`authorNickname`、`authorAvatar`、`content`、`images`、`tags`、`likeCount`（number）、`commentCount`（number）、`status`、`createdAt`。注意这里不表示当前用户是否已点赞。

原始 `Post` 字段为 `id`、`authorId`、`content`、`images`、`tags`、`likeCount`、`status`、`createdAt`。

### 6.4 编辑自己的社区帖

```http
PUT /api/community/posts/{id}
```

请求体字段及规则与发布相同，三项均为完整替换值。仅作者可编辑 `VISIBLE` 帖子。成功返回更新后的 `PostResp`。

### 6.5 删除自己的社区帖

```http
DELETE /api/community/posts/{id}
```

仅作者可删除自己的 `VISIBLE` 帖子。成功 `data=null`；实际为逻辑删除，`status` 改为 `DELETED`。

### 6.6 点赞/取消点赞

```http
POST /api/community/posts/{id}/like
```

无请求体。每次调用切换点赞状态，成功 `data` 为操作后的点赞总数（number），**不是是否已点赞的布尔值**。前端可根据调用前状态自行切换图标，或另行维护当前用户点赞状态。

### 6.7 查询评论

```http
GET /api/community/posts/{postId}/comments
```

成功返回按 ID 正序排列的评论：

| 字段 | 类型 |
|---|---|
| `id`, `postId`, `authorId` | number |
| `authorNickname`, `authorAvatar` | string/null |
| `content` | string |
| `replyToId` | number/null |
| `createdAt` | string |

### 6.8 发表评论或回复

```http
POST /api/community/posts/{postId}/comments
```

```json
{
  "content": "评论内容",
  "replyToId": null
}
```

`content` 必填、最多 500 字。普通评论省略 `replyToId` 或传 `null`；回复时传同帖评论 ID，不能跨帖回复。成功返回原始 `Comment`：`id`、`postId`、`authorId`、`content`、`replyToId`、`createdAt`。评论创建后应重新查询评论列表以取得作者昵称等展示字段。

### 6.9 上传图片

```http
POST /api/community/upload
Content-Type: multipart/form-data
```

表单字段：`file`（文件）。要求非空、最大 5 MB，扩展名仅支持 `jpg`、`jpeg`、`png`、`gif`、`webp`。

成功 `data` 为可直接保存到资料或帖子字段的相对路径：

```json
{"code": 0, "message": "ok", "data": "/uploads/<uuid>.png"}
```

展示图片时拼接后端基础地址，例如 `http://localhost:8080/uploads/<uuid>.png`。上传文件通过 `GET /uploads/{filename}` 公开访问。

## 7. 通知

### 7.1 我的通知

```http
GET /api/notify
```

成功返回当前用户按 ID 倒序排列的通知：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id`, `userId` | number | 通知与接收人 ID |
| `type` | string | 通知类型 |
| `content` | string | 展示文本 |
| `refId` | number/null | 关联业务 ID；订单相关通知为订单 ID |
| `read` | boolean | 是否已读 |
| `createdAt` | string | 创建时间 |

当前订单和申诉流程可能产生：`ORDER_CREATED`、`ORDER_ACCEPTED`、`ORDER_DELIVERED`、`ORDER_COMPLETED`、`ORDER_CANCELLED`、`APPEAL_CREATED`、`APPEAL_WITHDRAWN`。前端遇到未知类型时应使用通用样式，避免无法展示。

### 7.2 标记已读

```http
POST /api/notify/{id}/read
```

无请求体，只能操作自己的通知。成功 `data=null`。没有“一键全部已读”和未读数接口。

## 8. 评价

### 8.1 评价订单

```http
POST /api/reviews
```

```json
{
  "orderId": 1,
  "content": "沟通及时，完成质量很好"
}
```

`content` 必填、最多 500 字。仅 `COMPLETED` 订单的买卖双方可互相评价，每个用户对同一订单最多评价一次。成功 `data` 为评价 ID。当前没有评分字段。

### 8.2 查询用户收到的评价

```http
GET /api/reviews/user/{userId}
```

成功返回该用户收到的、按 ID 倒序排列的评价：

| 字段 | 类型 |
|---|---|
| `id`, `orderId`, `fromUserId`, `toUserId` | number |
| `content` | string |
| `createdAt` | string |

## 9. 全局搜索

```http
GET /api/search?keyword=快递
```

`keyword` 为必填查询参数；空白按空字符串处理。成功：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "posts": [],
    "tradePosts": []
  }
}
```

- `posts`：原始社区 `Post[]`，匹配 `VISIBLE` 帖子的 `content`，按 ID 倒序。
- `tradePosts`：`TradePost[]`，仅匹配 `OPEN` 交易帖的标题，按 ID 倒序。
- 空关键词会返回全部可见社区帖和全部开放交易帖，前端应避免无意义的全量搜索。

## 10. 学生举报

```http
POST /api/reports
```

```json
{
  "targetType": "POST",
  "targetId": 1,
  "reason": "包含不当内容"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `targetType` | 是 | `POST`（社区帖）/ `TRADE_POST`（交易帖）/ `USER`（用户） |
| `targetId` | 是 | 被举报对象 ID |
| `reason` | 是 | 非空白，最多 200 字 |

成功 `data=null`。同一举报人对同一对象已有 `PENDING` 举报时不能重复提交。该接口返回举报提交成功，不返回举报记录 ID。

## 11. 私信与 WebSocket

### 11.1 查询聊天记录

```http
GET /api/chat/history?withUserId=2
```

`withUserId` 必填，表示对方用户 ID。成功返回双方按 ID 正序排列的 `Message[]`：

| 字段 | 类型 |
|---|---|
| `id`, `fromId`, `toId` | number |
| `content` | string |
| `createdAt` | string |

### 11.2 建立 WebSocket

```text
ws://localhost:8080/ws/chat?token=<URL编码后的JWT>
```

生产环境 HTTPS 对应使用 `wss://`。握手不使用 `Authorization` 请求头，而使用 `token` 查询参数。token 缺失、无效、过期或用户被封禁时握手失败。

### 11.3 发送消息

连接后发送 JSON 文本帧：

```json
{
  "toId": 2,
  "content": "你好，请问什么时候方便？"
}
```

`toId`、`content` 必须存在且非 `null`，否则连接以策略错误关闭。内容非空白、最多 1000 字，接收用户必须存在。消息会持久化，不要求接收方在线。

接收方在线时收到：

```json
{
  "id": 10,
  "fromId": 1,
  "toId": 2,
  "content": "你好，请问什么时候方便？"
}
```

业务校验失败时发送方收到：

```json
{"error": "消息不能为空"}
```

实时消息不包含 `createdAt`；需要完整记录时可重新查询历史。当前服务端只向在线接收方推送，不向发送方返回独立成功确认帧，也不提供在线状态、已读回执、断线补发或会话列表接口。

## 12. 管理员接口

管理员与用户一样通过 `POST /api/auth/login` 登录，以下接口均要求 `role=ADMIN`。

### 12.1 删除社区帖

```http
POST /api/admin/posts/{id}/delete
```

无请求体。将社区帖逻辑删除为 `DELETED`，成功 `data=null`。

### 12.2 关闭交易帖

```http
POST /api/admin/services/{id}/close
```

无请求体。尽管路径包含 `services`，实现会按 ID 关闭任意交易帖，将状态设为 `CLOSED`，成功 `data=null`。

**该接口只修改帖子状态，不取消订单、不退款、不结算，也不是申诉仲裁接口。** 存在进行中订单时不要将其当作资金处置操作。

### 12.3 封禁用户

```http
POST /api/admin/users/{id}/ban
```

无请求体。将用户状态设为 `BANNED`，成功 `data=null`。被封禁用户不能登录，已有 token 也会失效。当前没有用户列表、解封接口。

### 12.4 查询待处理举报

```http
GET /api/admin/reports
```

成功返回按 ID 倒序排列的 `PENDING` 举报：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id`, `targetId`, `reporterId` | number | 举报、对象、举报人 ID |
| `targetType` | string | `POST` / `TRADE_POST` / `USER` |
| `reason` | string | 举报原因 |
| `status` | string | 当前列表固定为 `PENDING` |
| `createdAt` | string | 举报时间 |

### 12.5 管理端尚未提供的接口

当前后端没有以下能力，管理端需要另行约定和开发，不能假设路径已存在：

- 用户列表、用户详情、解封；
- 全量交易帖列表、全量订单列表及订单管理；
- 申诉列表、申诉详情、仲裁、退款或放款；
- 举报详情、举报处理/驳回及处理结果通知；
- 管理员操作日志、统计看板、分类管理；
- 管理员独立注册、管理员资料与权限管理。

新增仲裁功能时应复用现有订单状态与钱包领域规则，不允许直接修改钱包余额来代替结算或退款。
