# 管理端接口验证手册

> 目的：不依赖管理前端，也能亲手验证 B1（审计日志）与 B2（订单只读）是否真的可用。
> 适用范围：`campus-bounty-user-backend` 的管理端接口。
> 一键脚本：`scripts/admin-smoke/smoke.py`

---

## 零、先分清两条验证路径

这是最容易搞混的一点：**「验证功能对不对」和「验证线上配置对不对」是两个不同的问题，需要不同的数据库。**

| 路径 | 数据库 | 能验证什么 | 会写数据吗 | 用哪个模式 |
|---|---|---|---|---|
| **A. H2 内存库** | `test` profile，Hibernate 自动建表，进程退出即消失 | 完整业务链路：注册 → 充值 → 发单 → 接单 → 管理员筛选 → 详情聚合 → 审计留痕 | 会，但只写在内存里，杀进程就没了 | `--mode full` |
| **B. 共享 MySQL** | `local` profile，团队共用真库 | 服务能否启动、`ddl-auto=validate` 是否通过、真实库上的接口返回结构 | **不要写** | `--mode readonly` |

> 为什么不建议对真库跑 `full`：它会注册 4 个用户、发一笔悬赏、封禁一个人，这些都会留在团队的共享库里。而且真库 `max_user_connections` 只有 10，起服务本身就快占满了。

## 一、路径 A：H2 内存库 + 完整链路（推荐先跑这个）

### 步骤 1：编译并生成测试作用域 classpath

```bash
cd D:/aProject/campus-bounty-platform/campus-bounty-user-backend
export JAVA_HOME="/c/Program Files/Java/jdk-17.0.19"     # 本机默认是 JDK 11，必须覆盖
./mvnw -q -DskipTests test-compile
./mvnw -q dependency:build-classpath -Dmdep.outputFile=target/cp.txt -Dmdep.includeScope=test
```

### 步骤 2：用 test profile 启动服务

```bash
cd D:/aProject/campus-bounty-platform/campus-bounty-user-backend
export JAVA_HOME="/c/Program Files/Java/jdk-17.0.19"
CP="target/classes;target/test-classes;$(cat target/cp.txt)"
"$JAVA_HOME/bin/java" -cp "$CP" com.campus.bounty.BountyApplication --spring.profiles.active=test
```

看到 `Started BountyApplication` 即成功。**这个窗口要保持开着**，另开一个终端跑下一步。

> 注意不能用 `./mvnw spring-boot:run -Dspring-boot.run.useTestClasspath=true`，实测该参数不生效，`application-test.yml` 进不了 classpath，会因 `JWT_SECRET` 占位符解析失败起不来。

### 步骤 3：跑一键验证

```bash
cd D:/aProject/campus-bounty-platform
python scripts/admin-smoke/smoke.py --mode full
```

期望输出（节选）：

```
[1] admin 登录
  [PASS] admin 登录成功                          role=ADMIN
[3] 学生被挡在管理端之外（B1/B2 鉴权）
  [PASS] 学生访问日志 403/40300                  status=403 code=40300
...
[4] 真实业务链路：充值 -> 发悬赏 -> 接单
  [PASS] 发布者充值 100
  [PASS] 余额 100、冻结 0                        balance=100.0 frozen=0.0
  [PASS] 发布 20 元悬赏                          postId=1
  [PASS] 发布后余额 80、冻结 20（钱确实被扣住）    balance=80.0 frozen=20.0
  [PASS] 他人接单转 IN_PROGRESS                  status=IN_PROGRESS
...
结果：17 通过，0 失败
```

**最有说服力的是「发布后余额 80、冻结 20」这条**：它证明管理端看到的订单背后确实有真实资金被冻住，不是一张空表。

### 步骤 4：杀掉服务，数据自动消失

```bash
taskkill //F //IM java.exe
```

## 二、路径 B：共享 MySQL + 只读探针

### 步骤 1：启动 local profile

```bash
cd D:/aProject/campus-bounty-platform/campus-bounty-user-backend
export JAVA_HOME="/c/Program Files/Java/jdk-17.0.19"
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

启动日志里**不能出现** `Schema-validation: missing table [xxx]`。出现了就是库里缺表缺列，见 §四。

### 步骤 2：跑只读探针

```bash
cd D:/aProject/campus-bounty-platform
python scripts/admin-smoke/smoke.py --mode readonly
```

只读模式不下单、不封人，只验证：鉴权是否生效、两个接口是否 `code=0`、筛选是否工作、订单不存在是否返回 `40000`。

### 步骤 3：收工前必须停服务

真库连接数上限 10，不停服务的话你自己用任何客户端都连不上：

```bash
taskkill //F //IM java.exe
```

## 三、不用脚本，手工验证（答辩演示用）

脚本适合自己核对。如果要给老师演示，一条条敲更直观——用 `curl` 或 Postman 都行。

### 3.1 拿 admin token

```bash
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
```

返回里 `data.token` 就是后面要用的 token（很长一串）。

> 密码是 `admin123`，不是学生默认的 `123456`。这个账号由 `AdminBootstrap` 在 `local`/`test` profile 自动创建。

### 3.2 查审计日志（B1）

```bash
TOKEN="把上一步的 token 粘这里"
curl -s "http://localhost:8080/api/admin/logs" -H "Authorization: Bearer $TOKEN"
curl -s "http://localhost:8080/api/admin/logs?action=BAN_USER" -H "Authorization: Bearer $TOKEN"
```

期望：`{"code":0,"message":"ok","data":[...]}`。`data` 是数组，每项含 `adminId`/`action`/`targetType`/`targetId`/`detail`/`createdAt`。

### 3.3 查订单列表（B2）

```bash
curl -s "http://localhost:8080/api/admin/orders" -H "Authorization: Bearer $TOKEN"
curl -s "http://localhost:8080/api/admin/orders?postType=BOUNTY&status=IN_PROGRESS" -H "Authorization: Bearer $TOKEN"
curl -s "http://localhost:8080/api/admin/orders?buyerId=3" -H "Authorization: Bearer $TOKEN"
curl -s "http://localhost:8080/api/admin/orders?from=2026-11-01T00:00:00&to=2026-11-30T23:59:59" -H "Authorization: Bearer $TOKEN"
```

六个参数都可以单独用，也可以组合：`status` / `postType` / `buyerId` / `sellerId` / `from` / `to`。

### 3.4 查订单详情（B2 核心）

```bash
curl -s "http://localhost:8080/api/admin/orders/1" -H "Authorization: Bearer $TOKEN"
```

返回 `data` 里有六块，对账时要逐个看：

| 字段 | 含义 |
|---|---|
| `order` | 订单本体：金额、状态、买卖双方 id |
| `post` | 订单对应的交易帖：标题、类型、价格 |
| `buyer` / `seller` | 用户摘要（**只有** id/username/nickname/avatar/contact/role/status/createdAt） |
| `walletLogs` | 该订单的资金流水，正序：首笔 `FREEZE`（冻结），结算后是 `PAY`/`INCOME` |
| `appeals` | 该订单的历史申诉，倒序 |

### 3.5 验证「改不了」这件事

管理端对订单是只读的，这是设计约束。你可以试着调一个不存在的订单：

```bash
curl -s "http://localhost:8080/api/admin/orders/99999999" -H "Authorization: Bearer $TOKEN"
```

期望 `{"code":40000,...}`，HTTP 状态仍是 200——业务错误走 code，不走 HTTP 状态码。

再试一个学生 token 打管理端接口，期望 HTTP 403 + `code=40300`。

## 四、常见失败与对应原因

| 现象 | 原因 | 处理 |
|---|---|---|
| `不支持发行版本 17` | `JAVA_HOME` 指向 JDK 11 | `export JAVA_HOME="/c/Program Files/Java/jdk-17.0.19"` |
| 启动报 `JWT_SECRET` 占位符解析失败 | `application-test.yml` 没进 classpath | 用 §一步骤 2 的显式 classpath 启动，别用 `spring-boot:run` |
| 启动报 `Schema-validation: missing table [xxx]` | 库里缺表缺列 | 需要执行 DDL，见 `docs/管理端后端板块实施台账.md` §四 |
| `has exceeded the 'max_user_connections'` | 共享库连接上限 10，已被 H2/应用占满 | 先 `taskkill //F //IM java.exe` 再查库 |
| `smoke.py` 报 `无法连接` | 服务没起来或端口不对 | 先 `curl http://localhost:8080/api/admin/orders`，未登录应返回 401 |
| 脚本里注册返回 `code=40000` | 用户名必须是 4–20 位 | 脚本已用 `vpub<数字>` 这类短名，自定义时注意长度 |
| `data` 是空数组 | 库里没有数据 | 真库正常；要看非空数据用 `--mode full` 对 H2 跑 |

## 五、脚本退出码

- `0`：全部断言通过
- `1`：有失败项，末尾会列出失败名称

放进 CI 或提交前自检都可以直接用它。
